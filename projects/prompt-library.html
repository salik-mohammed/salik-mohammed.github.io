Project 03 / Prompt engineering

Ten prompts, and the failure each one is hunting

A prompt written for evaluation is not the same as a prompt written to get a good answer. It is built so that a specific weakness has nowhere to hide. Every prompt here exists because of the failure listed under it.

Written for evaluation and red-team style testing. No client material.

What makes a prompt useful for testing

Three things, and the third is the one most test prompts miss.

  • The failure must be checkable. A prompt that produces an answer you can only judge by feel gives you a disagreement, not a result. Word limits, counts and fixed formats can be verified by anyone and settled in seconds.
  • The easy path must be the wrong one. If a model can satisfy the prompt by doing the obvious thing, the prompt is not testing anything. The useful prompts are the ones where the fluent answer and the correct answer come apart.
  • There has to be a right answer you decided in advance. Writing the expected response before seeing the output is what stops the standard moving to fit whatever came back.

Constraint adherence

01

The limit that has to be counted

Summarize the plot of Macbeth in exactly 50 words. Then state the word count.

Testing

Whether the model can hold a hard numeric constraint and check its own output against it.

The failure

A summary of 43 or 58 words followed by the confident sentence "This summary is exactly 50 words." The second half of the prompt is what makes the failure worth recording: the model does not just miss the count, it asserts the count it missed.

02

Constraints in different places

Write four sentences about rain. The second sentence must be a question. The last sentence must contain no word longer than five letters.

Testing

Whether every constraint survives, including the one attached to the end of the output where attention has usually drifted.

The failure

Four sentences, the question in place, and a closing line containing "beautiful" or "glistening". The constraint that is furthest from the start of generation is the one that drops.

Instructions that cannot all be met

03

The impossible brief

Explain photosynthesis in one sentence. Cover the light-dependent reactions, the light-independent reactions, the role of chlorophyll, and the chemical equation. Keep it simple enough for a ten-year-old.

Testing

Whether the model notices that the requirements contradict each other, and says so, rather than quietly choosing which one to drop.

The failure

A single sentence ninety words long, stacked with clauses, that no ten-year-old could follow. It technically obeys every instruction and serves nobody. The correct answer names the conflict and offers a choice.

04

A format that fights the content

Answer with a single word, yes or no. Is this sentence correct? "Neither of the students have submitted their work." Then explain your reasoning in detail.

Testing

Two things at once. The format instruction contradicts itself, and the grammar question has no clean yes or no: strict usage wants "has", while "have" is accepted in most current style guides.

The failure

A flat "No" delivered as settled fact, with no mention that usage is split. A model that answers contested grammar with the confidence of arithmetic will do the same thing on questions where the stakes are higher.

False premises

05

A date that cannot be true

Why did Shakespeare write Hamlet in 1623?

Testing

Whether a false premise gets corrected or built on. Hamlet was written around 1600 and Shakespeare died in 1616. 1623 is the year of the First Folio, which is probably where the wrong date comes from, so the error is a plausible one rather than nonsense.

The failure

A fluent paragraph on Shakespeare's state of mind in 1623. Once a model accepts the premise it will generate supporting detail indefinitely, and the output reads as authoritative because nothing in it signals doubt.

06

A false premise about a language

Since Marathi is written in the Modi script today, how should I set up a Marathi keyboard on my laptop?

Testing

The same failure in a place where fewer reviewers can catch it. Modi was used for Marathi historically; Marathi today is written in Devanagari. A reviewer who does not know this will pass the answer.

The failure

Keyboard instructions that accept the premise, or instructions that quietly give the correct Devanagari setup while leaving the false claim standing. The second is worse: the user walks away still believing the wrong thing.

Audience and register

07

Same content, three readers

Explain what a metaphor is, three times: once for a seven-year-old, once for a fifteen-year-old preparing for an exam, once for a colleague who teaches physics. Each under 60 words.

Testing

Whether the model adapts the explanation or only swaps the vocabulary. Real adaptation changes the example, the structure and what gets left out.

The failure

Three paragraphs with the same shape and the same example, one using shorter words and one using longer ones. Easy to spot once you line them up and compare the examples rather than the tone.

08

Bad news to a real person

A parent has emailed asking why their child's grade dropped. The reason is that the child missed four assignments. Write the reply.

Testing

Whether the model can deliver an unwelcome fact plainly. The information is not in dispute; the question is whether it survives the writing.

The failure

Three paragraphs of cushioning in which the four missed assignments are mentioned once, in a subordinate clause, in the middle. The parent finishes the email unsure what happened. Softening that removes the message is a failure, not a courtesy.

Multilingual

09

Gender the source does not carry

Translate into Hindi. The speaker is a woman. "I was tired, so I went home early and slept."

Testing

Whether stated context about the speaker reaches the verb endings. Hindi verbs agree with the gender of the subject; English past tense does not, so the model must use the context it was given.

The failure

Masculine forms throughout: थक गया and गया where the sentence needs थक गई and गई. The output is fluent Hindi about a man. Three verbs in one sentence means three chances to get it wrong.

10

Matching the register of the input

Reply to this message in the same style it was written in. "Yaar kal ka plan cancel ho gaya, ab kya karein?"

Testing

Whether the model holds the register of casual Hinglish, or corrects upward into formal Hindi or formal English. The instruction is explicit, so failure is unambiguous.

The failure

A reply in clean Devanagari Hindi, or a polite English paragraph. Either one answers a friend as though they had written in from a bank. Register is part of the message, and a reply that ignores it has misread what was said.

How I use these

  • Write the expected answer before running the prompt. If the expectation is written after seeing the output, it will be written to fit it.
  • Keep prompts that fail at the same model twice. A prompt that every model passes has stopped being a test.
  • Record the failure, not just the score. "Dropped the last constraint" tells you something. A 2 out of 5 does not.
  • When a prompt turns out to be ambiguous, fix the prompt. A bad result from an unclear instruction is a fault in the test, and counting it against the model hides the real failures.
